# 말끔 — 메일 정리 데스크

받은편지함을 **나와의 관련도**와 **긴급도**로 자동 분류해서, 정말 봐야 할 메일만 남겨 주는 웹앱입니다.

> 문제 정의: 불필요한 참조 메일 과다로 인한 업무 지연
> 근본 원인(5 Whys): 수신 시점에 메일을 관련도·긴급도로 자동 분류하는 장치가 없다

## 화면

| 메뉴 | 하는 일 |
|---|---|
| 요약 대시보드 | 오늘 받은 메일, 지금 처리할 메일, 자동 정리 건수, 오발송 의심 |
| 분류함 | 모든 메일을 로직 트리의 한 칸에 분류. 분류 근거 확인, 분류 직접 수정 |
| 숨긴 메일 요약 | 자동 보관·후순위로 보낸 메일 점검, "이건 중요해요"로 되돌리기 |
| 업무 프로필 | 이름·메일·팀·업무 키워드·관심 주제·발신자 규칙 |
| 메일 연동 설정 | 데모 / Gmail / Outlook 선택과 앱 등록 안내 |

## 샘플 계정

왼쪽 위 워크스페이스 버튼에서 바꿀 수 있습니다. 김신입 계정에는 최근 5일 동안 받은 메일 280통, 나머지 두 계정에는 최근 30시간 동안 받은 메일 74통씩 들어 있습니다. 프로필과 고친 분류 규칙도 계정별로 따로 저장됩니다.

## 기능

- **F1 수신 위치 판별**: 받는 사람(To) / 참조(CC) / 팀 전체 주소를 구분
- **F2 업무 프로필**: 키워드·관심사·발신자 규칙으로 홍보·스터디 메일 판별. 언어 학습 메일은 관심 주제에 그 언어(예: 영어)를 적어 둔 경우에만 남김
- **F3 긴급도·요청 감지**: 내 이름, 요청 표현, 마감 표현으로 상단 고정·브라우저 알림 / 후순위
- **F4 오발송 감지**: 제목 태그·인사말 이름이 나와 다르면 표시, 회신 초안 생성 (발송은 직접)
- **F5 안전장치**: 숨긴 메일 요약, 사용자가 고친 분류를 발신자 규칙으로 학습

## 메일 연동 (읽기 전용)

### Gmail
1. Google Cloud Console에서 프로젝트를 만들고 Gmail API 사용 설정
2. OAuth 동의 화면(외부·테스트) 구성, 내 계정을 테스트 사용자로 추가
3. OAuth 클라이언트 ID(웹 애플리케이션) 생성, 승인된 JavaScript 원본에 `https://dhkdch1999.github.io` 추가
4. 앱의 "메일 연동 설정"에 클라이언트 ID 입력 (범위: `gmail.readonly`)

### Outlook (Microsoft 365)
1. Microsoft Entra 관리 센터 → 앱 등록 → 새 등록
2. 플랫폼: 단일 페이지 애플리케이션(SPA), 리디렉션 URI: `https://dhkdch1999.github.io/mail/`
3. API 권한: Microsoft Graph `Mail.Read`, `User.Read` (위임됨)
4. 앱의 "메일 연동 설정"에 애플리케이션(클라이언트) ID와 테넌트 입력

## 보안 원칙

- 권한은 읽기 전용만 사용. 메일 발송·삭제·이동 기능 없음
- 토큰은 `sessionStorage`에만 보관 (탭을 닫으면 사라짐)
- 메일 내용은 브라우저 메모리에서만 처리하고 외부 서버로 보내지 않음
- 저장소에 API 키·시크릿 없음 (클라이언트 ID는 공개값)
- 프로필·고친 분류 규칙만 이 브라우저의 `localStorage`에 저장
